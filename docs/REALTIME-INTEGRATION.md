# 实时接入说明

## 已实现

- `GET /api/xui/snapshot`：当前试运行阶段仅登录 WF3，读取全部入站、启用状态和累计上下行流量。其他节点暂未接入。
- `POST /api/xui/toggle`：按服务器简称与入站 ID 读取原配置，只修改 `enable` 后提交，避免丢失其他字段。
- 前端始终二次确认开关操作；账号密码不进入浏览器包或 Git。

## 凭据

发布后在 Sites 环境变量中配置：

- `XUI_USERNAME`：x-ui 共用账号，标记为 secret。
- `XUI_PASSWORD`：x-ui 共用密码，标记为 secret。

如果以后各服务器使用不同凭据，将 `credentials()` 替换为按 alias 查询的凭据引用，不要把凭据加进 `XUI_NODES`。

## 活跃 IP 和归属地

x-ui 原版入站列表只提供累计流量和启用状态，不提供每个端口的实时来源 IP。完整实现需要每台服务器部署一个只读采集代理，周期性读取 TCP/UDP 连接或流量日志，再向控制台的 HTTPS 入口回传：

```json
{
  "alias": "t4",
  "collectedAt": "2026-09-08T19:00:00+08:00",
  "ports": [{
    "port": 55555,
    "clients": [{ "ip": "203.0.113.10", "connections": 3 }]
  }]
}
```

归属地应在中心端用可更新的 GeoIP 数据库解析。不要把地理位置当作封禁依据；它只适合调查和筛选。UDP 无连接语义，不能只靠 `ss` 的已建立连接数量统计，需要短周期 nftables/eBPF/日志采样。

## 上线安全边界

- 当前面板入口是公网 HTTP。正式使用开关前，优先为面板启用 HTTPS、反向代理鉴权或私有 HTTP 隧道。
- 站点应保持 owner-only 或严格白名单访问。
- 每次写操作记录操作者、时间、服务器、入站 ID、旧状态、新状态和结果。
- 批量控制必须预览影响范围，并设置失败即停；不自动重启 x-ui、Xray 或服务器。
